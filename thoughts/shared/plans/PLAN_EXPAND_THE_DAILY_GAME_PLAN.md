# Plan: Expand the Daily Game-Theory Advisor

## Context

The advisor has three layers: `social_media_gt.py` is the exact Fraction/SymPy/Z3 paper engine; `advisor.py` maps language to its ten fixed scenarios; `webapp.py` and `mcp_server.py` expose Gradio and four MCP tools. The expansion adds general-game formulation, estimation, equilibrium/mechanism analysis, robustness, simulation, and saved cases without changing the paper engine.

The executed stress plan records TC-006: a first-price auction ran all ten unrelated paper scenarios. The research outline and field schema are `advisor-pipeline-stress-testing/outline.yaml` and `advisor-pipeline-stress-testing/fields.yaml`. General-game intake needs explicit unsupported/clarification decisions before any solver runs.

## Decisions

- Keep `social_media_gt.py` and `test_social_media_gt.py` unchanged; add general-game capabilities in separate modules.
- Keep paper-scenario analysis as a distinct Gradio mode and existing MCP contract.
- Exact claims require exact-rational inputs or explicit decimal-to-rational conversion, a solver witness, and independent exact checks; model assumptions remain conditional.
- Label requests/outcomes `exact_verified|approximate|solver_unavailable|error|unsupported|invalid|needs_confirmation|clarification|no_agreement`; exact claims require exact-rational inputs or explicit decimal-to-rational conversion, a solver witness, and independent exact checks. Return each method's witness, objective, expected utilities, checks, certificate when applicable, model scope, assumptions, and provenance. Never silently substitute an approximate result for an exact request; assumptions remain conditional.
- Use PyGambit 16.7.0 for supported exact finite equilibria; use OpenSpiel 2.0.2 only for approximate learning/search/simulation.
- When Stackelberg followers have tied best responses, report both leader-favorable and follower-favorable outcomes.
- Save cases for one owner only; require explicit save and encrypt case contents at rest.
- Keep repository MIT; PyGambit GPL-2.0-or-later review and notices gate every image push/deployment, including private registry/homelab.

## Approach

Order: define model, objective, and data contracts first. Exact/approximate solvers then build independently. Advisor integration depends on both. Persistence can proceed beside solvers. UI/MCP and deployment depend on the core contracts. Tests prove each slice and full path.

1. Add `game_models.py`. Define `PlayerSpec(id,name,role,utility_unit,normalization_basis)`, `ParameterSpec(name,value,lower_bound,upper_bound,prior,unit,normalization_basis,provenance)`, and a `GameSpec` union of `NormalFormGame`, `ExtensiveFormGame`, `BayesianGame`, `StackelbergGame(stage_game,leader_id,follower_id,commitment_mode,tie_policy)`, `RepeatedGame`, `BargainingSpec`, `MechanismSpec`, and `OpenSpielGame(game_id,parameters)`. `GameSpec` fields include `schema_version=1`, `template_id`, `template_options`, ordered players, `action_sets[player_id]`, parameters keyed by `ParameterSpec.name`, information structure, commitment/mediator rights, `analysis_role`, objective, assumptions, and provenance map `json_pointer -> {origin,source}`. A payoff cell is a rational value or affine `{constant,coefficients}`; coefficient keys must match declared parameter ids. Utilities use the player's unit/base; aggregate only matching units or explicit rational conversions. Exact values are ints or fraction/decimal strings; reject bool, NaN, infinity, missing payoffs, invalid probabilities, and arbitrary expression text. Parameters have exactly one mode: point, closed interval, or finite rational prior `[{value,probability}]` summing to one. Solves require point values; intervals are only bounded estimation/sensitivity inputs; priors are used only in an explicit Bayesian type/information model. Never average unknown payoffs. After confirmation, estimated decimal strings become rational point inputs while retaining `origin=estimated`; proof claims apply only to those displayed points.

Normal-form payoffs are rows `{action_profile:{player_id:action_id},utilities:{player_id:PayoffValue}}` covering the full Cartesian product. Extensive nodes are `{id,actor,edges,information_set_id,terminal_utilities}` with edges `{action_id,next_node,probability?}`; chance probabilities sum to one and information sets are `{id,player_id,node_ids,action_ids}`. A finite `BayesianGame` declares `type_spaces[player_id]`, a common rational prior over every type profile, type payoffs, and private-own-type observations; public signals are represented as chance/information sets in ExtensiveFormGame. Bayesian strategies map each own type to an action distribution. A `BargainingSpec` has exactly two players, finite rational feasible utility vectors, rational disagreement point, and `randomization=allowed|not_allowed`; `allowed` requires an explicit binding contract/mediator right and convexifies the feasible set. Its solution maximizes the Nash product of gains over individually-rational points. A `RepeatedGame` wraps a finite `NormalFormGame` stage game with positive integer `horizon`, rational `discount_factor` in `[0,1]`, and `monitoring=perfect_public|private`; cumulative utility is the unnormalized sum `Σ δ^t u_t`. Named repeated policies require two actions per player and explicit cooperation/defection action ids; simulation supports only `perfect_public`. Infinite-horizon games, Folk-theorem claims, private-monitoring strategies, and repeated-game equilibria are unsupported. Validate reachability, acyclicity, full terminal utilities, and perfect recall before refinement claims. `StackelbergGame` commitment mode is `pure|mixed`; `tie_policy` is fixed to `report_both`.

2. Define `ObjectiveSpec(kind,direction,player_id=None,weights=None)`. `kind` is `player_utility|social_welfare|revenue|maximin|weighted_utility`; `direction` is `maximize|minimize`; `player_utility` requires a player; weighted weights are nonnegative rationals summing to one; social welfare is the unweighted utility sum; revenue is total player payments to designer and is valid only for MechanismSpec; maximin means maximize the minimum expected player utility and rejects minimize. Mechanism design requires an objective. No objective means no Nash ranking, no CE optimization beyond feasibility, and no recommendation. A Nash objective optimizes only over a complete certified equilibrium set; CE over its full polytope; Stackelberg separately reports both tie policies; mechanism design over its feasible finite mechanism set. An incomplete witness never proves global optimality.

3. Define mechanism schema. `MechanismSpec` fields are `designer_id`, `mechanism_kind=direct|vcg|optimal_auction`, `design_mode=verify_candidate|optimize|generate_vcg`, finite `type_spaces`, rational prior, reports, outcomes, `feasible_outcomes`, `value_table[player_id][type_id][outcome_id]`, `outside_option[player_id][type_id]`, allocation, transfers, `utility_model=quasilinear`, `ic_concept=DSIC|BIC`, `ir_scope=ex_post|interim|ex_ante`, `budget_rule=none|no_deficit|budget_balance`, and objective. Direct, VCG, and optimal-auction reports equal the declared type ids for each player. Each outcome encodes a complete allocation, including explicit opt-out; `value_table` records each player's value for the assigned allocation, and opt-out value equals the stated outside option. Reports list ids per player; outcomes have unique ids; `feasible_outcomes` maps each report profile to allowed outcomes; allocations map report profiles to nonnegative rational probabilities summing to one; transfers map report profiles to rational payments, positive from player to designer. The outside option never defaults to zero. DSIC checks truthful reporting against every unilateral misreport at every type profile; BIC checks prior-expected utility for each type. Ex-post IR compares every type profile to its outside option; interim IR compares each type's expectation; ex-ante IR compares the prior expectation. No-deficit requires nonnegative revenue at every profile; budget balance requires zero net transfer. `verify_candidate` requires supplied allocation/transfers; `optimize` makes them LP variables over the finite feasible outcome set. VCG is selected only by `mechanism_kind=vcg`; it fixes DSIC, ex-post IR, social-welfare maximization, no budget constraint, and report-independent `vcg_tie_rule=lexicographic_outcome_id`. Its feasible outcome set must be invariant across reports; absent-player set `F_-i` consists of outcomes assigning player i opt-out. Compute an efficient allocation then `payment_i=max_{a in F_-i} sum_{j!=i}v_j(a,theta_j)-sum_{j!=i}v_j(a*(theta),theta_j)`; require nonnegative values and verify exact DSIC/IR. `optimal_auction` fixes BIC, interim IR, and expected-revenue maximization; user supplies budget rule. Reject incompatible overrides. `mechanism_optimum` is unavailable in `verify_candidate` mode.

4. Add `compile_template(template_id,template_options,game_data) -> GameSpec` to `game_models.py`; templates are typed forms/validators, not hidden formulas. `pricing_auction` options are `auction_rule=first_price|second_price`, finite types/prior, bid grids, and `tie_rule=player_order|uniform_random`; player_order uses ordered players, uniform_random splits allocation equally across tied highest bids. The compiler creates exact utilities: first price charges a winning bid; second price charges the highest losing bid. `security_patrol` takes finite schedules, targets, exact coverage probabilities, and covered/uncovered payoff tables, compiling to StackelbergGame. `negotiation` takes a finite offer tree and exact terminal utilities, compiling to ExtensiveFormGame. `bargaining` takes the finite utility vectors, disagreement point, and explicit randomization right for BargainingSpec. `public_goods` takes finite contribution actions and a complete payoff table. `mechanism_design` maps to MechanismSpec; VCG uses its fixed rule above. `multi_agent_learning` compiles to `OpenSpielGame(game_id,parameters)` with allowlist `kuhn_poker|leduc_poker|matrix_pd|tic_tac_toe`; CFR/MCCFR only support the first two. `custom` takes the canonical form directly. The LLM proposes typed field values; it never calculates payoffs or executes formulas.

5. Add `game_solvers.py` and `game_lp.py`. Implement exact `solve_exact_game`, `verify_nash`, `verify_bayesian_nash`, `verify_spne`, `verify_correlated_equilibrium`, `solve_nash_bargaining`, `solve_stackelberg`, `verify_stackelberg`, `verify_mechanism`, `solve_rational_lp`, and `verify_lp_optimality`; keep `verify_epsilon_nash` as an exact verifier. Method compatibility: `pure_nash` for NormalFormGame and Stackelberg stage game; `mixed_nash` for two-player NormalFormGame and finite two-player extensive games convertible to strategic/sequence form within profile cap; `bayesian_nash` for finite private-own-type BayesianGame, using pure contingent plans for any player count and mixed contingent-plan conversion only for two players, within profile cap; `subgame_perfect` only finite perfect-information ExtensiveFormGame; `correlated_equilibrium` only finite normal form with confirmed mediator; `nash_bargaining` only two-player BargainingSpec; `stackelberg` only StackelbergGame; `mechanism_optimum` only MechanismSpec `design_mode=optimize`. An incompatible requested method returns `unsupported` before worker launch. `methods=None` selects compatible exact methods only. `epsilon_nash` is separate and approximate, supported only for finite NormalFormGame; it requires positive rational `epsilon`. Define `payoff_range=max(all pure-profile player payoffs)-min(all pure-profile player payoffs)`; if range is zero, every profile is an exact equilibrium. Otherwise start PyGambit `simpdiv_solve` from the uniform rational mixed profile, pass positional arguments `(uniform_profile, epsilon/payoff_range, 2, 10000)` for start, maxregret, refine, leash; the documented criterion bounds maximum regret by `maxregret*payoff_range`. Rationalize/normalize its candidate and verify maximum unilateral regret exactly. Return `epsilon_verified` only when regret <= epsilon; leash exhaustion or failed verification returns `solver_unavailable`, never an exact-Nash claim. For two-player `BargainingSpec`, no-randomization solves by exact finite enumeration; binding randomization computes the exact rational convex hull and evaluates Nash product at every vertex and every stationary point on each hull edge. Return all tied outcomes and a rational mixture witness with an exact global certificate; no individually-rational point with both gains positive returns `no_agreement`. N-player mixed games without an exact solver/certificate return `solver_unavailable`. Use PyGambit `enumpure_solve`, `enummixed_solve`, `lcp_solve`, and `lp_solve` only in documented domains; convert outputs to `Fraction` and independently verify. `enummixed_solve` returns extreme points, not every profile in a continuum; `lcp_solve` is one witness. For exact LPs, implement `solve_rational_lp(c,A_ub,b_ub,A_eq,b_eq,bounds)` with `sympy.solvers.simplex.linprog`; rationalize inputs with SymPy `Rational`, translate bounded variables by exact shifts/reflections, split free variables into nonnegative parts, turn equalities into paired inequalities, track objective offsets, and canonicalize to `max c^T x, A x<=b, x>=0`. Solve the primal as min `-c^T x`; build the dual min `b^T y` subject to `A^T y>=c,y>=0`, solve separately, verify canonical primal/dual feasibility, map the primal witness back and verify original constraints, then compare original objective with canonical primal/dual objectives including offsets, all exactly with `Fraction`. Do not use SciPy floats as exact witnesses. Cap canonicalized LPs at 2,000 variables and 10,000 constraints; infeasible, unbounded, or over-limit returns `solver_unavailable`. Use exact LP for CE/Stackelberg/mechanism optimization. CE without objective is feasibility only. For pure Stackelberg, enumerate every leader action and follower best-response set, then return both tie-policy outcomes. For mixed leader-favorable Stackelberg, enumerate follower actions as selected responses and maximize leader payoff subject to weak best-response inequalities. For follower-favorable mixed Stackelberg, enumerate follower-response subsets up to 12 actions; require equal follower utilities within a subset and strict gap against outsiders. First maximize the gap and discard infeasible/nonpositive-gap subsets; the all-actions subset has no gap constraint. For each nonempty region maximize the worst leader payoff across tied responses. At its candidate optimum, fix the objective and maximize strict gap again to prove attainment. Compare only nonempty regions. If the best supremum is unattained, return `solver_unavailable` with its exact supremum and no lower attained result. Report both tie policies for pure and mixed commitment. Cap leader and follower actions at 12. Trembling-hand perfection is unsupported without a separate certificate.

Add `game_estimation.py` and `game_simulation.py`. `estimate_game_parameters(spec,observations,method,confirmed_by_user)` supports `conditional_logit|qre_marginals`; successful estimates are always `approximate`, never exact proofs. `conditional_logit` accepts `[{type_profile,action_profile,count}]` with complete profiles and positive integer counts, fixes lambda=1, and fits only interval-bounded affine coefficients with `P(a_i|a_-i,type)=softmax(U_i)`; point parameters stay fixed and priors are rejected. Use SciPy MLE and per-parameter profile-likelihood 95% intervals, reoptimizing other coefficients and using `2*(ell_max-ell)<=3.84`; intervals are nominal pseudo-likelihood because responses in joint profiles are dependent. If an MLE or interval endpoint touches a user bound, the profile likelihood is flat/non-finite, or an interval cannot close, return `unidentified` with `boundary_limited=true` where applicable. `qre_marginals` accepts `[{player_id,action_id,count}]` with nonnegative integer counts and positive total per player; it requires known point payoffs. At each of 145 log-spaced lambdas `1e-6..1e6` on the principal QRE branch, call `pygambit.qre.logit_solve_lambda(game,[lambda])` and accept a profile only if `abs(profile.lam-lambda)/lambda <= 1e-8`. Compute multinomial log-likelihood `sum_i sum_a n[i,a]*ln(sigma[i,a])`; a positive-count action with computed zero probability makes that lambda unusable, never clip probabilities. Refine each bracketed local maximum with `scipy.optimize.minimize_scalar` in log-lambda and each 3.84 profile-likelihood crossing with `scipy.optimize.brentq`. Return all disconnected 95% interval components. Drop missed lambda points and record them; if any missed point prevents establishing the MLE or interval endpoint, return `solver_unavailable`; if a component touches a grid boundary, return `unidentified`. QRE results state `correlation_retained=false`; do not call `logit_estimate` or fit behavior-profile data. Type priors use observed labels only; latent types require an explicit model. `apply_estimates(game_spec,estimate_result,parameter_ids,confirmed_by_user)` never mutates the supplied spec; it copies selected displayed decimal strings through `Fraction(text)` into point parameters, drops their interval/prior fields, and records `origin=estimated` plus method/data provenance. Require fresh explicit confirmation before applying and another confirmation before solving. `analyze_sensitivity(spec,assignments,confirmed_by_user)` accepts at most 256 complete rational assignments inside declared interval/prior support and returns per-point exact results plus finite-set best/worst; elapsed total budget adds `not_covered`. `simulate_game(spec,algorithm,policies,episodes,seed,confirmed_by_user,iterations=None)` returns approximate seed/budget and per-player episode-total mean, variance, and 95% Student-t interval computed across independent episodes. Simulation requires `episodes`; CFR/MCCFR require positive `iterations` plus evaluation episodes; `seed` is a nonnegative integer. For repeated policies use `{kind:named_repeated,players:{id:{name,cooperate_action_id,defect_action_id}}}`; `name=always_cooperate|always_defect|tit_for_tat|grim_trigger`. Always-cooperate/defect choose the named action; tit-for-tat starts with cooperation then chooses its own cooperation/defection action according to the opponent's previous public action; grim-trigger cooperates until any public defection then defects forever. These policies require two players, two actions each, and perfect public monitoring. Algorithms are `simulation|cfr|mccfr`; normal-form policy is `{kind:mixed,players:{id:{action_id:rational_probability}}}`, extensive policy is `{kind:behavior,players:{id:{information_set_id:{action_id:rational_probability}}}}`. CFR/MCCFR only support allowlisted two-player zero-sum OpenSpiel games; evaluate returned policies by seeded episodes and report supported NashConv as approximate. General-sum/repeated learning returns simulation metrics, never equilibrium/convergence claims.

## Assumptions & contingencies

- Exact results apply to the explicitly represented finite model only. Exact checks do not prove inferred payoffs match reality or contracts are legally enforceable.
- Unknown payoffs stay unknown until the user supplies a point, interval, finite prior, or identifiable affine utility model. MLE/QRE values remain estimates. After user confirmation, convert the estimate's decimal serialization to a rational point; exact solver checks then prove only the equilibrium properties conditional on that point, while reports preserve `provenance=estimated`.
- Exact Nash bargaining is limited to two players and finite rational utility sets; cooperative core/Shapley, n-player bargaining, and continuous feasible sets return `unsupported`. General-sum RL, latent-type estimation without an explicit type model, and infinite-horizon repeated equilibrium also return `unsupported`. The `RepeatedGame` variant supports finite-horizon simulation only; users may enter a finite expanded game as ExtensiveFormGame for exact SPNE within tree limits. Exact SPNE covers finite perfect-information trees. Finite imperfect-information games may return strategic-form Nash, not sequential-equilibrium claims. Continuous-action and oversized models remain approximate or unsupported unless a selected exact solver certifies them.
- The confirmation flag records an explicit caller action; it is not an authentication mechanism. The web login protects the single-owner case library. MCP HTTP remains loopback-only.
- Gambit issues #1179 and #1180 document `logit_estimate` nontermination/near-pure nonidentification and `logit_solve_lambda` returning a profile whose actual lambda misses the requested value. Do not call `logit_estimate`; use bounded normal-form `logit_solve_lambda` profile likelihood in the timed worker, verify every returned `profile.lam`, and reject missed points that affect the estimate or interval. Return `unidentified` or `solver_unavailable` rather than arbitrary precision.
- PyGambit 16.7.0 has no Linux/macOS wheels and builds from sdist with Cython, matching Python headers, and a C++ compiler. Build in the Docker builder stage; local macOS installs need Xcode Command Line Tools. OpenSpiel 2.0.2 has Python 3.12 wheels for Linux x86_64/aarch64 and macOS arm64. Keep repository MIT license unchanged. Complete GPL-2.0-or-later review and required notices/source availability before any image push, including private registry/homelab.
- Exact resource caps are 10,000 pure profiles and 10,000 tree nodes; estimation accepts at most 100,000 observations; approximate iterations/episodes cap at 100,000. Keep current 1 CPU/1Gi deployment limits; exceedance or timeout returns a structured failure, never silent fallback.
- Deployment must provision `GT_APP_USERNAME`, `GT_APP_PASSWORD`, and a 32-byte Base64 `GT_CASE_ENCRYPTION_KEY` in `game-case-secrets`, plus a persistent volume mounted at `/data`; set `GT_CASE_DB_PATH=/data/game-cases.sqlite3`. Missing credentials, key, or volume fails closed. Back up the encryption key separately; losing it makes saved cases unreadable.
- Keep case retention indefinite until owner deletion; do not auto-expire cases. Keep records single-owner; do not add sharing or multi-account behavior.
